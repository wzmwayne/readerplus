# 插件开发指南（纯 Dart 插件体系）

ReaderPlus 的插件是**纯 Dart** 实现的：脚本用 [Hetu Script](https://pub.dev/packages/hetu_script)，
书源也可以写成**声明式规则**（JSON）。两者由同一个执行器运行 —— 同一个 isolate、
同一套宿主能力、同样的超时与取消语义。

> 历史说明：早期版本用 Python（serious_python）跑插件，已完全移除。
> 旧 Python 脚本**不兼容**，请按本指南重写（格式更简单：不需要 `SCRIPT` 声明、
> 不需要 params.json/manifest.json，直接调用下面的能力函数即可）。

## 一、为什么是纯 Dart

| 事项 | 说明 |
|---|---|
| 多端一致 | 脚本引擎与宿主能力都是 Dart 代码，Android / Linux 行为完全一致，没有按平台分发二进制的问题 |
| 崩溃隔离 | 脚本在**独立 isolate** 里执行；`while(true){}` 会被硬超时 `Isolate.kill` 掉，应用毫发无损 |
| 真取消 | 到点即杀 isolate，不是"标记一下稍后处理" |
| 沙盒 | 脚本**只能**调用下面列出的宿主函数：没有文件系统、没有裸网络、没有进程能力 |
| 实时日志 | `log()` 逐条回调到界面（不显示进度条） |

## 二、快速开始

脚本就是一段 Hetu 代码。最小示例（把输入文本原样存成产物）：

```hetu
var text = inputText('raw.txt')
log("输入 ${text.length} 字符")
saveOutput('out.txt', text)
result('ok')
```

放置与使用：**书源页 → 右上角 + → 选择 `.ht` 文件**（或 `.json` 规则文件），
之后勾选它并搜索即可。内置示例随应用打包，首次进入自动写入：
`内置：TXT 清洗转 EPUB`、`内置：本地测试书源`。

## 三、脚本类型声明（必须写，避免被错用）

每个脚本**头部**都要声明自己的类型（纯 Dart 静态解析，不执行代码）：

```hetu
// @script kind=source name="我的书源"
```

| kind | 含义 | 出现位置 |
|---|---|---|
| `source` | 书源（搜索/详情/下载） | 「书源」页 |
| `clean` | 清洗（TXT → EPUB） | 「脚本管理」清洗分类 |
| `tool` | 其它工具脚本（**默认值**） | 「脚本管理」其他分类 |

- 支持多行续写：`// @script kind=clean` 后面跟 `// name="…"`、`// capabilities=…`；
- `name` 会作为显示名（可选）；
- **不写声明、或写了未知类型 = tool**：最保守的默认，**不会被当成书源误用**。

管理入口：**设置 → 脚本管理**，可按类型分组查看、编辑、删除、从模板新建。
编辑保存后会重新解析声明，类型随之更新。

## 三、脚本语言（Hetu）必读约定

这些约定都是踩过坑总结的，写脚本时按它来：

1. **字符串拼接**：字符串与数字**不能**用 `+`。用插值：`log("共 ${n} 条")`。
2. **异步**：宿主函数返回 Dart `Future`，用 `.then(callback)` 续跑；
   回调**必须用花括号函数体** —— `=> { ... }` 会被当成返回结构体的表达式，
   是本次开发中最后踩到的坑：
   ```hetu
   httpGet('https://example.com').then((response) {
     log("状态 ${response['status']}")
     result(response['text'])
   })
   ```
3. **返回值交回**：用 `result(...)`。对象字面量在 Hetu 里是**结构体**，
   引擎会自动递归转成 JSON 结构交给宿主；需要严格 JSON 文本时用内置
   `JSON.stringify(...)`。集合可用 `Map()` / 列表字面量 `[...]`。
4. **判等与成员**：`==` 判等；结构体用 `s['field']` 或 `s.field` 取值。
5. **外部函数不需要声明**：引擎会自动为下面的能力注入 `external function` 声明。

## 四、宿主能力（全部由 Dart 提供，跨端一致）

### 4.1 日志与结果

| 函数 | 说明 |
|---|---|
| `log(message)` | 写一条日志（实时显示在书源页的"执行过程"面板） |
| `result(value)` | 交回结果（最后一次生效；脚本结束前至少调用一次） |

### 4.2 参数与输入输出

| 函数 | 说明 |
|---|---|
| `param(name, fallback?)` | 读宿主参数：`task`（`search` / `download`）、`query`、`id`、`page` 等 |
| `params()` | 读出全部参数 |
| `inputText(name, encoding?)` | 读输入文本（`encoding` 缺省 `auto`：先严格 UTF-8，失败再按 GBK） |
| `inputBytes(name)` | 读输入字节 |
| `saveOutput(name, bytes)` | 写产物到本次运行的产物目录，返回完整路径 |

### 4.3 HTTP（既简单，也高自由度）

| 函数 | 说明 |
|---|---|
| `httpGet(url, headers?, wantBytes?)` | 简单 GET，返回 `{status, reason, url, headers, text}` |
| `httpPost(url, body?, contentType?, headers?, wantBytes?)` | 简单 POST |
| `httpRequest(options)` | 高自由度请求，见下表 |

**取原始字节**：加 `wantBytes: true`（`httpRequest` 里写 `'wantBytes': true`），
响应会**额外**带上 `bytes`（原始字节列表）。用于图片、二进制接口、自定义加密体：

```hetu
httpRequest({'url': coverUrl, 'wantBytes': true}).then((r) {
  // r['bytes'] 是字节列表，可直接交给 aesDecrypt / base64Encode / saveOutput
  saveOutput('cover.jpg', r['bytes'])
  log('封面字节数：${r['bytes'].length}')
})
```

不传 `wantBytes` 时不返回 `bytes`（大响应不会白白展开成列表）。

`httpRequest` 的 `options`：

| 字段 | 说明 |
|---|---|
| `url`、`method` | 必填 URL 与方法（GET/POST/PUT/DELETE/…） |
| `headers` | 多值头：`{'X-A': ['1','2']}` |
| `rawHeaderLines` | 逐行原样加头：`['X-A: 1', 'Cookie: a=b']` |
| `body` | 文本或字节数组 |
| `contentType` | 如 `application/x-www-form-urlencoded` |
| `cookies` | `{'k':'v'}`；宿主另有 cookie 罐自动收/发 |
| `connectTimeoutMs` / `idleTimeoutMs` | 超时控制 |
| `followRedirects` / `maxRedirects` | 重定向控制 |
| `proxy` | 形如 `PROXY host:port`（或 `DIRECT`） |
| `allowBadCertificate` | 是否允许自签证书（默认不允许） |
| `wantBytes` | `true` ⇒ 响应额外带 `bytes`（原始字节列表） |

### 4.3.1 询问用户（ask）

脚本运行到一半需要用户补参数时（API Key、章节范围、分类…），可以提问：

```hetu
// 明文询问（默认）：输入框正常显示，问题与回答都会进日志，便于排查
ask('要下载哪些章节？例如 1-20').then((reply) {
  if (reply['ok']) { runDownload(reply['answer']) } else { result({'items': []}) }
})

// 秘密询问：输入框遮挡，且**回答绝不写进日志**（只记录长度）
ask('请输入该源 API Key', {'secret': true, 'default': '上次的密钥'}).then((reply) {
  if (reply['ok'] == false) { result({'items': []}) }
  else { runSearch(reply['answer']) }
})
```

| 参数 | 说明 |
|---|---|
| 第一个参数 | 问题文本（必填） |
| `secret` | `true` ⇒ 秘密询问：输入遮挡 + **回答不入日志**（默认 `false` 明文） |
| `default` | 预填到输入框里的默认答案（可省略） |

返回 `{ok, answer}`：

| 情况 | 结果 |
|---|---|
| 用户点了确定 | `{ok: true, answer: '输入内容'}` |
| 用户点了取消 | `{ok: false, answer: ''}` |
| 没有界面（将来后台运行） | `{ok: false, answer: ''}` + 日志提示 |
| 同一次运行超过 10 次提问 | `{ok: false, answer: ''}` + 日志提示（防狂弹框） |

**写法要点**：

- 用 `.then(...)` 接回答，**不需要轮询** —— isolate 的事件循环负责调度，等待期间零 CPU 占用；
- 依赖答案的逻辑写在回调里；推荐"先取参数、再调用具名函数"的写法，业务逻辑保持顺序：

```hetu
var task = param('task', 'search')

fun runSearch(apiKey) { /* 这里完全按顺序写 */ }

if (task == 'search') {
  var key = param('apiKey', '')
  if (key == '') {
    ask('请输入 API Key', {'secret': true}).then((reply) {
      if (reply['ok']) { runSearch(reply['answer']) } else { result({'items': []}) }
    })
  } else { runSearch(key) }
}
```

- **提问期间不计时**：不会因为用户打字慢被 60 秒搜索超时或下载上限杀掉（计时会暂停、回答后重新开始）；
- 点搜索页的**「取消」**会同时关闭输入框（并按取消处理），不会留下一个永远不返回的对话框；
- 回答**不会被保存**：下次运行会再问一次。想只问一次，就把它作为 `param` 传入，或用脚本自己的逻辑缓存。

### 4.3.2 脚本工作目录（沙箱）

每次运行都有一个**脚本可完全操控的目录**，读写增删随便用（放临时文件、缓存、分段下载都行）：

| 函数 | 说明 |
|---|---|
| `sandboxDir()` | 工作目录绝对路径（不存在会自动创建） |
| `fileWrite(name, bytes)` | 写文件，返回绝对路径（父目录自动建） |
| `fileRead(name)` / `fileText(name)` | 读字节 / 读文本（UTF-8 容错） |
| `fileList([sub])` | 列出文件（相对名） |
| `fileExists(name)` / `fileSize(name)` / `fileDelete(name)` | 判断 / 大小 / 删除 |

```hetu
var dir = sandboxDir()
log('工作目录：' + dir)
fileWrite('cache/page1.json', httpTextBody)
var names = fileList()
if (fileExists('cache/page1.json')) { log('缓存 ${fileSize('cache/page1.json')} 字节') }
```

**边界（安全）**：只能使用**工作目录内的相对路径**。`../`、绝对路径（`/etc/…`）、
盘符（`c:/…`）都会被直接拒绝并抛错 —— 脚本出不去这个目录。

**生命周期**：宿主自动为每次运行创建临时工作目录，**运行结束即清理**；
若作业自带产物目录（例如 TXT→EPUB），则保留产物、不做清理。

### 4.4 文本 / 编码 / 正则 / URL

| 函数 | 说明 |
|---|---|
| `decode(bytes, encoding?)` | 字节转文本（UTF-8 / GBK / Latin-1 …） |
| `regexp(pattern, input, group?)` | 首个匹配（`group` 缺省 `0`）；支持内联标志 `(?m)(?i)(?s)` |
| `regexpAll(pattern, input, group?)` | 全部匹配，返回列表 |
| `urlJoin(base, relative)` | 相对地址解析 |
| `urlEncode(value)` | URL 编码 |

### 4.5 EPUB 3 与文本处理

| 函数 | 说明 |
|---|---|
| `splitChapters(text, pattern?)` | 按标题正则分章，返回 `[{title, body}, ...]` |
| `cleanText(text, rules)` | 规则清洗：`[[正则, 替换], ...]`（**只做规范化，不删正文内容**） |
| `epubBuild(options)` | 生成 EPUB 3 字节 |

`epubBuild` 的 `options`：`{title, author, language, chapters:[{title, body}], cover:[字节], coverName}`。
产物**严格符合 EPUB 3.3**（官方 EPUBCheck 5.3.0 校验：0 fatals / 0 errors / 0 warnings / 0 infos）。

### 4.6 密码学与压缩（自建／私人书源必备）

全部为**纯 Dart** 实现，Android 与 Linux 行为一致；实现经过公开标准向量校验
（FIPS-197 AES、NIST SP 800-38A CBC、RFC 1321/4231 摘要与 HMAC）。

| 函数 | 说明 |
|---|---|
| `digest(algo, input, encoding?)` | `md5` / `sha1` / `sha256` / `sha512`，返回小写 hex |
| `hmac(algo, input, key, encoding?)` | `md5` / `sha1` / `sha256` / `sha512`，返回小写 hex |
| `base64Encode(bytes)` / `base64Decode(text)` | Base64 双向（解码自动忽略空白，另支持 URL-safe） |
| `hexEncode(bytes)` / `hexDecode(text)` | 十六进制双向（解码自动忽略非 hex 字符） |
| `aesDecrypt(options)` / `aesEncrypt(options)` | AES-128/192/256，`ecb` / `cbc`，`pkcs7` / `iso7816` / `none` |
| `xorBytes(bytes, key, keyEncoding?)` | 按字节循环 XOR |
| `gunzip(bytes)` / `gzipBytes(bytes)` | gzip 解压／压缩 |

`input` / `key` 的 `encoding` 可为 `utf8`（默认）、`base64`、`hex`、`latin1`；
也可以直接传字节列表（如 `httpRequest` 返回的 `bodyBytes`）。

`aesDecrypt` / `aesEncrypt` 的 `options`：

| 字段 | 说明 |
|---|---|
| `data` | 数据（解密一般是接口返回的密文；加密是明文） |
| `key` | 密钥，长度必须 16/24/32 字节 |
| `mode` | `cbc`（默认）/ `ecb` |
| `iv` | CBC 的初始向量（16 字节）；ECB 不需要 |
| `padding` | `pkcs7`（默认）/ `iso7816` / `none`（无填充，长度须为 16 的倍数） |
| `keyEncoding` / `ivEncoding` | `utf8`（默认）/ `hex` / `base64` / `latin1` |
| `inputEncoding` | 不填时：**解密默认 `base64`，加密默认 `utf8`** |

**关于 gzip**：带 `Content-Encoding: gzip` 的响应由宿主**自动解压**，脚本无需处理；
只有当接口返回的是**没有响应头的裸 gzip**（例如某个 `.gz` 文件、或密文里再套一层压缩）时，
才需要显式调用 `gunzip(bytes)`。

**实战示例：私有接口返回 AES-CBC + Base64 密文**

```hetu
httpRequest({
  'url': 'https://example.com/api/search',
  'method': 'POST',
  'body': 'q=' + urlEncode(param('query', '')),
  'contentType': 'application/x-www-form-urlencoded'
}).then((response) {
  // 1) 接口返回 { data: "<base64 密文>", sign: "..." }
  var envelope = JSON.parse(response['text'])

  // 2) 解密：AES-128-CBC + PKCS7，密钥由 hex 给出
  var plainBytes = aesDecrypt({
    'data': envelope['data'],
    'key': '0123456789abcdef0123456789abcdef',
    'keyEncoding': 'hex',
    'iv': 'abcdef0123456789abcdef0123456789',
    'ivEncoding': 'hex',
    'mode': 'cbc',
    'padding': 'pkcs7'
  })

  // 3) 若明文里又套了一层 gzip，再解一层
  var text = decode(plainBytes, 'utf8')
  if (regexp('^\\x1f\\x8b', hexEncode(plainBytes), '0') != null) {
    text = decode(gunzip(plainBytes), 'utf8')
  }

  // 4) 校验签名（可选）：md5(密文 + salt)
  log('签名：' + digest('md5', envelope['data'] + 'salt'))

  var payload = JSON.parse(text)
  result(payload)
})
```

要点：
- **不要**自己在脚本里拼 HTTP 头做 gzip 请求 —— 宿主已自动协商与解压；
- 密钥/IV 建议由 `param()` 传入（便于换源），或写死在书源里（自建源通常没问题）；
- 若接口用 `ECB`，把 `mode` 改 `ecb` 并去掉 `iv`；
- 若用「无填充 + 自己裁剪」，`padding` 用 `none`（此时数据长度必须是 16 的倍数）。

Hetu 自带能力也可用：`JSON.parse/stringify`、`Map()`、列表、`Future` 等。

## 五、完整示例一：TXT 清洗转 EPUB

```hetu
var text = inputText('raw.txt')
// 只做规范化（去零宽/BOM），不删任何正文内容（包括广告行）
text = cleanText(text, [
  ['[\\u200b\\ufeff]', '']
])
var chapters = splitChapters(text, '^第[一二三四五六七八九十百千两0-9]+[章回节卷].*$')
log("切分得到 ${chapters.length} 章")

var options = {}
options['title'] = param('title', '未命名')
options['author'] = param('author', '佚名')
options['chapters'] = chapters
saveOutput('book.epub', epubBuild(options))
result('ok')
```

## 六、完整示例二：书源脚本（搜索 / 详情 / 下载）

一个脚本用 `param('task')` 区分三种任务：

```hetu
var task = param('task', 'search')

if (task == 'search') {
  var q = param('query', '')
  httpGet('https://gutendex.com/books?search=' + urlEncode(q)).then((r) {
    var raw = r['text']
    var parsed = regexpAll('"id":\\s*(\\d+)', raw, '1')
    var items = []
    for (var i = 0; i < parsed.length; i = i + 1) {
      var item = {}
      item['id'] = parsed[i]
      item['title'] = '待补充书名'
      items.add(item)
    }
    log("命中 ${items.length} 条")
    var payload = {}
    payload['items'] = items
    result(payload)
  })
} else if (task == 'detail') {
  var payload = {'id': param('id'), 'title': '书名', 'description': '简介'}
  result(payload)
} else {
  var payload = {'id': param('id'), 'chapters': [{'title': '第一章', 'body': '正文'}]}
  result(payload)
}
```

要点（**没有独立的"取详情"任务**，只有 search 与 download）：
- 搜索必须**一次带回全部字段**：
  `{items: [{id, title, author, cover, intro, description}, ...]}`，`id` 必填；
  - `cover` 是封面图地址；没有就留空字符串（界面会显示占位封面，**保证每条结果都有封面**）；
  - `description`/`intro` 是简介，点击结果时**直接展示**，不再发第二次请求。
- 下载交回 `{chapters: [{title, body}, ...]}`，**并可补充作者与封面**：
  - `author`：作者名（优先于搜索结果）；
  - `cover`：封面图地址（App 抓取字节后嵌入 EPUB 的 cover-image）；
  - `coverData`：封面字节的 base64（脚本已拿到字节时用，优先于 `cover`）。

  这样"搜索页元数据薄、下载页信息全"的站也能拿到正确作者与封面。

**封面可以内联传（base64）**，三种形态按优先级取用：

| 写法 | 说明 |
|---|---|
| `coverData: '裸 base64'` | 最高优先；脚本已用 `wantBytes` 拿到图片字节时用 |
| `cover: 'data:image/jpeg;base64,XXXX'` | data URI，次优先 |
| `cover: 'https://…/x.jpg'` | 图片地址，最后兜底；都没有或加载失败 ⇒ 界面显示占位封面 |

内联示例（把图片字节转成 base64 交给界面，不依赖外部图床）：

```hetu
httpRequest({'url': 'https://example.com/cover.jpg', 'wantBytes': true}).then((r) {
  var payload = {}
  payload['items'] = [
    {'id': '1', 'title': '书名', 'coverData': base64Encode(r['bytes'])}
  ]
  result(payload)
})
```

## 七、声明式书源（规则，JSON）

简单的书源不必写脚本。规则文件示例：

```json
{
  "id": "gutenberg",
  "name": "古腾堡（示例）",
  "version": 1,
  "search": {
    "url": "https://gutendex.com/books?search={{query}}&page={{page}}",
    "format": "json",
    "list": "results[*]",
    "fields": {
      "id": "id",
      "title": "title",
      "author": "authors[0].name",
      "cover": "formats['image/jpeg']",
      "description": "summaries[0]"
    }
  },
  "download": {
    "url": "https://www.gutenberg.org/cache/epub/{{id}}/pg{{id}}.txt",
    "format": "text"
  }
}
```

> 规则与脚本一样**没有 detail 段**：搜索的选择器里把 `cover`、`description` 一并取出来即可。

| 字段 | 说明 |
|---|---|
| `url` | 支持 `{{query}}`/`{{page}}`/`{{id}}` 模板（自动 URL 编码） |
| `format` | `json` / `xml` / `text` / `html` |
| `list` | 列表选择器，如 `results[*]`（仅搜索用） |
| `fields` | 字段 → 选择器：`a.b[0].c`、`a[*]`、XML 元素名；含 `cover`/`description` |
| `chapter_pattern` | 下载时按此正则分章（缺省整本当一章） |

规则与脚本**共用同一套宿主能力**（同一条 HTTP 栈、同一隔离、同一取消），
因此规则也能用上多值头、代理、超时等设置（写在 `headers` 等字段里）。

**运行上限**：搜索固定 60 秒上限；**下载默认不限制**（大书慢慢跑），
可在「设置 → 脚本 → 下载脚本运行上限」改为 5 / 30 分钟或 2 小时；
任何时刻都能在搜索页点**「取消」**强制停止（`Isolate.kill`，真取消）。

## 八、调试

- 「**执行过程（实时）**」标题行右侧就是**取消**按钮：点它就强制停止所有在跑的脚本
  （`Isolate.kill`，真取消）；搜索与下载期间都会显示不确定进度条；
- 结束原因会写清楚，不再混为一谈：
  - **被取消 / 超时** ⇒ "脚本已被强制停止"；
  - **异常退出**（isolate 未交回结果就结束）⇒ "脚本异常退出（isolate 意外结束，未交回结果）"；
  - 脚本自己 `throw` ⇒ 显示具体错误文本；
- **转屏不中断**：脚本跑在独立 isolate 里，横竖屏切换只改布局，不重建页面状态，
  搜索中的实时日志与结果都会保留；
- 书源页的**执行过程面板**实时显示 `log()` 输出与失败原因；
- 开发者页（设置 → 关于 → 连点「版本」7 次）可看应用日志文件；
- 常见错误：
  - `字符串 + 数字` → 用插值；
  - `.then((x) => { ... })` → 改花括号函数体；
  - `result` 没被调用 → 脚本结束前必须交回结果；
  - 忘记 `param('task')` 分支 → 只有 `search` 与 `download` 两种；
  - 搜索没带 `cover`/`description` → 结果会缺封面图与详情（占位符会顶上）。
